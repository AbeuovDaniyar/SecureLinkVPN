& "C:\Users\Danny\Senior project\SecureLink\client\SecureLink.Client\bin\Release\net8.0-windows\SecureLink.Client.exe"

Step 3 — Connect to New York (1m 30s)
-------------------------------------

DO: Make sure the region reads New York (US-East) → click the power button.
EXPECT: "Connected — New York (US-East)" and the timer starts.

SAY: "The client generated its own WireGuard key pair — the private key never leaves this machine. Only the public key was sent to the backend, which registered it on the relay."

RUN in the Admin window (my public IP is now the relay's):

curl.exe -s https://ifconfig.me

EXPECT: 165.227.213.133

RUN (the tunnel is running as a Windows service):

sc.exe query 'WireGuardTunnel$securelink' | Select-String STATE

EXPECT: RUNNING

RUN (the live tunnel, as WireGuard sees it):

wg show securelink

EXPECT: a peer with endpoint 165.227.213.133:51820 and a recent handshake.

RUN (the kill switch is on):

netsh advfirewall show allprofiles firewallpolicy | Select-String Firewall

EXPECT: BlockInbound,BlockOutbound

SAY: "While connected, the kill switch sets Windows Firewall to block all outbound traffic except the encrypted packets to the relay and traffic going through the tunnel. The Downloaded and Uploaded counters in the app come straight from WireGuard."

SAY: "Now I'll simulate the tunnel dropping by removing the tunnel service while the kill switch stays on. Nothing should reach the internet."

Step 5 — Disconnect (45s)
-------------------------

EXPECT: App shows "Disconnected".

RUN (the tunnel service is gone):

sc.exe query 'WireGuardTunnel$securelink' | Select-String "STATE|1060"

EXPECT: 1060 (the service does not exist)

RUN (the firewall is back to normal):

netsh advfirewall show allprofiles firewallpolicy | Select-String Firewall

EXPECT: BlockInbound,AllowOutbound

RUN (internet works again):

curl.exe -s -o NUL -w "%{http_code}" https://example.com

EXPECT: 200

SAY: "Disconnect removes the tunnel, restores the firewall, and tells the backend to remove my peer from the relay."

EXPECT:
  * "Checking for leftovers..." with the power button greyed out

DO: Click the power button → it connects normally (no "active session" error). Then click it again to Disconnect.

SAY: "On startup the app detects the leftover tunnel, firewall rules and server session from the crash, and cleans all of them up before Connect is allowed."

Step 9 — Admin functions (1m, optional)
---------------------------------------

Your account is already an admin. First paste this setup into the Admin window (lets PowerShell trust the server's certificate):

Add-Type -TypeDefinition 'using System.Net; using System.Net.Security; using System.Security.Cryptography; public static class SlPin { public static void On() { ServicePointManager.ServerCertificateValidationCallback = (s, c, ch, e) => e == SslPolicyErrors.None || (c != null && System.BitConverter.ToString(SHA256.Create().ComputeHash(c.GetRawCertData())).Replace("-", "") == "053F1809D67ED37B2A4AD5C3371CB70D0DE4994626886CC56DEA2CCCAD6D8713"); } }'; [SlPin]::On(); [Net.ServicePointManager]::SecurityProtocol = 'Tls12'; $api = "https://165.227.213.133"

DO: Click the power button in the app to connect (New York).

SAY: "Admins can see and revoke every active session. Admin accounts can't be self-registered — the flag is set on the server."

RUN (log in as admin — it asks for your email and password; the password stays hidden):

$em = Read-Host "Email"; $p = Read-Host "Password" -AsSecureString; $pw = [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($p)); $tok = (Invoke-RestMethod -Method Post "$api/api/auth/login" -ContentType "application/json" -Body (@{email=$em; password=$pw} | ConvertTo-Json)).token; $pw = $null; $h = @{ Authorization = "Bearer $tok" }; "logged in"

RUN (list all active sessions):

$s = Invoke-RestMethod "$api/api/admin/sessions" -Headers $h; $s | Format-Table userEmail, region, tunnelIp, startedAt

EXPECT: your session, region newyork, a 10.8.0.x address.

RUN (revoke it):

Invoke-RestMethod -Method Post "$api/api/admin/sessions/$($s[0].id)/revoke" -Headers $h; "revoked"

SAY: "Revoking removes my peer from the relay, so the tunnel stops passing traffic and the kill switch prevents any leak. The client isn't notified of revokes yet, so I disconnect."

DO: Click Disconnect in the app.

RUN (list again — the session is gone):

Invoke-RestMethod "$api/api/admin/sessions" -Headers $h | Format-Table userEmail, region, tunnelIp
